# SSAFY Algorithm Study

> **매주 정해진 알고리즘 문제를 함께 풀고, 서로의 접근 방식과 풀이 과정을 공유하며 문제 해결 능력을 키우는 스터디입니다.**

단순히 정답 코드를 제출하는 것에 그치지 않고, 문제를 해결하기 위해 사용한 알고리즘과 사고 과정을 설명할 수 있는 것을 목표로 합니다.

---

## 스터디 운영 규칙

### 진행 방식

* 아래 문제 목록을 **상단부터 순서대로 매주 4문제씩** 풉니다.
* 매주 **수요일 수업 종료 후 오프라인으로 모여** 풀이를 공유합니다.
* 각자 문제를 해결한 방법과 사용한 알고리즘을 설명합니다.
* 서로 다른 풀이가 있다면 시간 복잡도, 공간 복잡도, 코드 가독성 등을 비교합니다.
* 모임 전까지 해당 주차의 문제 풀이 코드를 GitLab 레포지토리에 제출합니다.
* 마지막 9주차는 남은 3문제를 풉니다.

### 문제를 해결하지 못한 경우

문제를 자신의 힘으로 끝까지 해결하지 못했더라도 반드시 해결된 코드를 제출합니다.

필요한 경우 다음 자료를 참고할 수 있습니다.

* 다른 사람의 풀이
* 알고리즘 강의 및 블로그
* 공식 문서
* GPT 등의 생성형 AI

단, 자신의 힘으로 해결하지 못하고 도움을 받은 문제는 코드 상단에 다음 내용을 주석으로 작성합니다.

1. 문제를 처음 보고 생각한 해결 방법
2. 직접 시도한 방법
3. 해결하지 못하고 막힌 부분
4. 참고한 내용 또는 질문한 내용
5. 참고 후 이해한 최종 해결 방법

```java
/*
 * [풀이 도움 여부]
 * GPT의 도움을 받아 해결
 *
 * [나의 생각 과정]
 * 1. 처음에는 모든 경우를 확인하는 완전탐색을 생각했다.
 * 2. 현재 상태에서 가능한 선택을 재귀적으로 탐색하려고 했다.
 * 3. 중복된 상태를 여러 번 확인하면서 시간 초과가 발생했다.
 *
 * [막힌 부분]
 * 같은 상태를 반복해서 탐색하지 않는 방법을 찾지 못했다.
 *
 * [참고한 내용]
 * GPT에게 현재 접근 방식의 시간 복잡도와 최적화 방법을 질문했다.
 *
 * [최종적으로 이해한 해결 방법]
 * 이미 계산한 상태를 저장하는 메모이제이션을 적용하여
 * 중복 탐색을 제거할 수 있다는 것을 이해했다.
 */
```

복사한 코드를 그대로 제출하는 것이 아니라, **코드의 동작 원리를 이해하고 직접 설명할 수 있는 상태**로 제출해야 합니다.

## 오프라인 모임 진행

매주 수요일 모임은 다음 순서로 진행합니다.

1. 해당 주차 문제의 해결 여부를 확인합니다.
2. 문제별로 각자의 접근 방식을 공유합니다.
3. 서로 다른 풀이 방법을 비교합니다.
4. 해결하지 못했던 문제의 막힌 지점을 공유합니다.
5. 더 좋은 풀이 또는 개선할 부분을 함께 정리합니다.
6. 다음 주차 문제를 확인합니다.

발표자는 별도로 정하지 않고, 문제마다 서로의 풀이를 자유롭게 공유합니다.

## 레포지토리 컨벤션

### 디렉터리 구조

각 주차 폴더 아래에 자신의 이름 또는 GitLab ID로 폴더를 생성합니다.

```text
.
├── README.md
├── week01
│   ├── 이름1
│   │   ├── SWEA_14510_나무_높이.java
│   │   ├── SWEA_5643_키_순서.java
│   │   ├── SWEA_1249_보급로.java
│   │   └── SWEA_1267_작업_순서.java
│   └── 이름2
├── week02
│   ├── 이름1
│   └── 이름2
└── ...
```

### 파일명 규칙

파일명은 다음 형식을 사용합니다.

```text
SWEA_문제번호_문제이름.확장자
```

예시:

```text
SWEA_14510_나무_높이.java
SWEA_5643_키_순서.java
SWEA_1249_보급로.java
```

공백 대신 언더스코어(`_`)를 사용합니다.

### 브랜치 전략

브랜치는 다음 형식으로 생성합니다.

```text
이름/week-주차
```

예시:

```text
seungeon/week-01
seungeon/week-02
```

한 주차의 문제를 모두 작성한 뒤 `main` 브랜치로 Merge Request를 생성합니다.

### 커밋 컨벤션

| 태그         | 용도               | 예시                                |
| ---------- | ---------------- | --------------------------------- |
| `solve`    | 문제 풀이 코드 제출      | `solve: SWEA 14510 나무 높이 풀이`      |
| `docs`     | 주석 및 풀이 설명 추가    | `docs: SWEA 14510 풀이 과정 정리`       |
| `refactor` | 동작은 같지만 코드 구조 개선 | `refactor: SWEA 1249 다익스트라 코드 개선` |
| `fix`      | 오답 또는 코드 오류 수정   | `fix: SWEA 5643 탐색 조건 수정`         |
| `chore`    | 폴더 구조 및 설정 변경    | `chore: 1주차 제출 폴더 생성`             |

한 커밋에는 가능하면 하나의 문제만 포함합니다.

```text
solve: SWEA 14510 나무 높이 풀이
solve: SWEA 5643 키 순서 풀이
```

### Merge Request 규칙

Merge Request 제목은 다음 형식을 사용합니다.

```text
[주차] 이름 문제 풀이
```

예시:

```text
[1주차] 최승언 문제 풀이
```

Merge Request 본문에는 다음 내용을 작성합니다.

```markdown
## 풀이한 문제

- SWEA 14510 나무 높이
- SWEA 5643 키 순서
- SWEA 1249 보급로
- SWEA 1267 작업 순서

## 도움을 받아 해결한 문제

- SWEA 14510 나무 높이
  - GPT에게 풀이 방향에 대한 도움을 받았습니다.
  - 코드 상단에 생각 과정을 정리했습니다.

## 공유하고 싶은 내용

- SWEA 1249는 다익스트라 알고리즘을 사용했습니다.
- 우선순위 큐에서 이미 처리된 좌표를 건너뛰는 방식으로 최적화했습니다.
```

## 코드 작성 규칙

* 제출하는 코드는 정상적으로 실행되어야 합니다.
* 문제의 입력 및 출력 형식을 준수합니다.
* 불필요한 디버깅 출력은 제거합니다.
* 변수와 메서드 이름은 역할을 이해할 수 있도록 작성합니다.
* 다른 사람의 코드를 참고했다면 그대로 복사하지 않고 직접 이해한 뒤 작성합니다.
* 도움을 받아 해결한 문제는 반드시 코드 상단에 자신의 생각 과정을 주석으로 남깁니다.
* 오프라인 모임에서 자신의 코드를 설명할 수 있어야 합니다.

코드 상단에는 필요에 따라 다음 정보를 작성할 수 있습니다.

```java
/*
 * 문제: SWEA 14510 나무 높이
 * 메모리: 27,000 KB
 * 실행 시간: 150 ms
 * 알고리즘: 그리디
 */
```

## 스터디 목표

* SW 역량평가 A형 문제에 익숙해집니다.
* 문제에 적합한 알고리즘을 선택하는 능력을 기릅니다.
* 자신의 풀이를 다른 사람에게 설명하는 능력을 기릅니다.
* 다른 사람의 코드를 읽고 장단점을 파악합니다.
* 해결하지 못한 문제도 포기하지 않고 끝까지 이해합니다.
* 단순한 정답 제출이 아니라 문제 해결 과정을 기록하는 습관을 만듭니다.

> 모르는 문제는 도움을 받아도 괜찮습니다.
> 다만, 도움을 받은 과정을 기록하고 최종 풀이를 자신의 말로 설명할 수 있어야 합니다.
